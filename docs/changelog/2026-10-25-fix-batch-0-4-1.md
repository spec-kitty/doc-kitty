# 2026-10-25 — `kind` required again, UTC dates and a stable Cucumber report

Four follow-ups to the 0.4.0 release, in one change. The decision about `kind`
is recorded in [ADR-0065](../adr/0065-kind-required-again.md); the
[0.4.0 to 0.4.1 guide](../migrations/0.4-to-0.4.1.md) lists what an adopter
does.

- **`kind` is required on every page again
  ([#219](https://github.com/spec-kitty/doc-kitty/issues/219)).** This is a
  breaking change. The frontmatter gate now fails a page without `kind`, as
  the convention and ADR-0009 always said. The build still renders such a
  page. A consumer can relax the field with `required_fields.optional: [kind]`
  in its charter.
- **Non-ISO dates read as UTC
  ([#234](https://github.com/spec-kitty/doc-kitty/issues/234)).** A written-out
  or numeric date with no zone, such as `May 1, 2024`, used to be read in the
  build machine's time zone. It is now read as UTC on every machine, and a
  date that names its zone keeps it. See the
  [metadata model](../architecture/metadata-model.md#instants).
- **A stable Cucumber report for the example
  ([#231](https://github.com/spec-kitty/doc-kitty/issues/231)).**
  `normalise-cucumber-report.mjs` removes what a run records about its machine
  and its moment, so regenerating `example/reports/cucumber.ndjson` with
  unchanged features gives the same bytes. Two real runs, from different
  directories and time zones, gave identical output.
- **Lock files untracked
  ([#232](https://github.com/spec-kitty/doc-kitty/issues/232)).** Seven
  transient `decisions/index.json.lock` files left in older missions are no
  longer tracked.
