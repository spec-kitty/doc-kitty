# Context

Doc Kitty turns a documentation tree into a browsable, agent-ready site. This
section explains the why and the what: the problem Doc Kitty solves, the
outcomes it is built for, the convention it renders, and why an AI-focused
company treats agents as first-class readers. Start here before the
architecture or guides.

## Why and what

- [Why docs next to code rot](./problem.md) — the recurring failure mode of
  docs-next-to-code: structure too rigid to grow, contents too hard to browse.
- [What Doc Kitty solves for](./what-we-solve-for.md) — the four outcomes:
  structure, maintainability, agent interoperability, and flexibility.
- [Agent-first documentation](./agent-first.md) — why AI agents are first-class
  readers here, not an afterthought.
