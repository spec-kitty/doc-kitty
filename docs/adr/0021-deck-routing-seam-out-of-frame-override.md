# ADR-0021: Decks render out-of-frame by a path-scoped Astro route override

## Status

Accepted. Implements the deck route left unspecified by
[ADR-0012](./0012-slide-decks-static-reveal-from-markdown.md) and
[ADR-0011](./0011-theme-slot-surface-and-per-kind-layouts.md) (which decided a
`Presentation` renders through a dedicated reveal route outside the docs frame).
**Amends ADR-0012 decision 1**: the switch is narrowed from "a `Presentation` page
*anywhere*" to **a `Presentation` page under `presentations/`** (see Decision 1 and
the amendment note below). Paired with
[ADR-0022](./0022-reveal-integration-and-token-theme.md) (reveal integration).

## Context

A deck stays a `docs`-collection page (`kind: Presentation`) so it keeps the whole
existing contract — the zod schema, the standalone validator, doc-sanity,
`related`/citation resolution, and the generators that read `collectDocEntries()`
(`src/lib/routes/shared.ts`). But ADR-0011/0012 require it to render **outside** the
Starlight frame, and the in-frame kind→layout registry
(`src/components/MarkdownContent.astro` → `resolveLayout` → `src/lib/manifest.ts`)
renders **inside** the Starlight shell — so a deck cannot be a kind→layout entry.

Starlight injects a **single `[...slug]` catch-all** over the entire `docs`
collection and exposes **no API to drop an entry** from its generated routes. ADR-0012
decision 1 says a `Presentation` "anywhere routes to the deck renderer"; that is
**not achievable**. A site-root `src/pages/[...slug].astro` would override Starlight's
catch-all *wholesale* (documented Astro override behaviour) and 404 every URL its
`getStaticPaths` omits — i.e. every documentation page. The only clean mechanism is a
**path-prefixed, higher-specificity** file route that shadows Starlight **only** under
`/presentations/*`. That mechanism forces the switch to be **path + kind**, and forces
"exclusion" to be re-described honestly as **route-priority shadowing**.

A second, quieter hazard: llms.txt and the agent API build a deck's URL from its
**collection slug** (`src/lib/routes/llms-txt.ts`, `agent-index.ts`), a *different*
code path from the deck route's `getStaticPaths` params. A trailing-slash or base
drift would list a URL that 404s while every lane stays green.

## Decision

1. **The switch is path + kind (amends ADR-0012 decision 1).** A deck renders
   out-of-frame iff it is `kind: Presentation` **and** lives under `presentations/`.
   ADR-0012 decision 1's "anywhere" is superseded by this ADR; `architecture/slide-decks.md`
   is amended to match. A `kind: Presentation` page filed **outside** `presentations/`
   is a **hard build/validator error**, never a silent in-frame render — so the
   invariant the route override depends on cannot be violated.
2. **The deck route is `src/pages/presentations/[...slug].astro`.** It runs
   `getStaticPaths()` over `getCollection('docs')` filtered to `kind: Presentation`,
   is statically prerendered (`export const prerender = true`), and server-renders
   `.reveal > .slides > section`. By path specificity it **shadows** Starlight's
   catch-all for `/presentations/*` only; every other URL still belongs to Starlight.
3. **Starlight's route is shadowed, not excluded.** The collection entry stays fully
   enumerated by Starlight (and therefore by the generators); Astro route priority is
   what makes the deck win the URL. The load-bearing invariant is therefore *"exactly
   one HTML is emitted at `/presentations/<deck>/`, and it contains `.reveal > .slides`
   — the deck — not the Starlight article shell,"* and it is **asserted at build**
   (`assert-build-artifacts.mjs`), not assumed.
4. **The deck-URL contract equals the generators' slug normalization.** The deck
   route's param→path reconstruction (trailing slash, site `base`) is defined to be
   byte-identical to the URL the sitemap filter and llms/agent generators emit from
   the collection slug. A build assertion checks the deck URL listed by llms.txt **and**
   the agent API equals the deck route's emitted path.
5. **Presentations are excluded from the in-frame autogenerated sidebar.** An in-frame
   sidebar link that ejects the reader out of the frame with no signal is wrong; decks
   are surfaced only through the presentations **overview page** (`kind: Hub`). (If
   Starlight cannot drop the sidebar node, the overview page is the canonical entry and
   the sidebar node is suppressed via the sidebar config.)

## Consequences

### Positive

- The deck is a first-class `docs` record (validated, discoverable, cited) **and**
  renders as a chrome-free reveal deck, with no separate collection to keep in sync.
- The out-of-frame boundary is a single, asserted invariant (one HTML, deck shell,
  parity URL) rather than an assumption.

### Negative

- The "anywhere" affordance ADR-0012 imagined is gone: decks must live under
  `presentations/`. This is a real narrowing, recorded as an amendment.
- The deck route re-implements a small amount of what Starlight's catch-all does
  (static path generation, URL normalization); the URL contract (Decision 4) must be
  kept in lockstep with the generators.

### Risks

- **Route-priority regressions.** An Astro upgrade that changed route-specificity
  ordering could silently un-shadow Starlight; the route-uniqueness build assertion
  (Decision 3) is the guard.
- **URL drift.** If the deck route and the generators diverge on trailing-slash/base,
  a listed URL 404s; the parity assertion (Decision 4) is the guard.

## Alternatives considered

### Option A: A separate `presentations` content collection

Rejected (and rejected by the mission owner). It decouples decks from the shared
validator, doc-sanity, and the generators, forcing every one of those to be re-wired
for a second collection — for no gain over keeping decks in `docs` and shadowing the
route.

### Option B: Site-root `src/pages/[...slug].astro`

Rejected. It overrides Starlight's catch-all wholesale and 404s every documentation
page whose slug the deck `getStaticPaths` does not emit. Only a path-prefixed route is
safe.

### Option C: `routeMiddleware` / redirect from the in-frame route

Rejected. A redirect still renders (or round-trips through) the in-frame page and does
not give a clean out-of-frame document; it also leaves the in-frame duplicate that
C-004 forbids.
