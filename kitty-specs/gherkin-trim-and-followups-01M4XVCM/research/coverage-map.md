## Row format

One table per suite family. IDs are `<family>-<nn>`. Families:
`PARSE` (parse, feature-core, view, select, anchors), `RENDER` (render, mdast, fence, fence-build),
`INCL` (include, docs-loader-includes, docs-loader-includes-build, agent-page-includes),
`GEN` (generate, codegen-guard, check-cli, options, load, integration, example, fixture-parity),
`RES` (results, results-render, results-build, scenario-index), `E2E` (tests/a11y/gherkin.spec.ts).

| Row | Behaviour (input class → output / warning / error) | Before (`file:test name`) | After (`file:test name` + asserting line) | Verdict | Security (C-006) | Break-checked |
|---|---|---|---|---|---|---|
| RES-01 | report status `failed` → badge `data-status="failed"` | `gherkin-results.test.ts:"maps cucumber-js failed"`; `…:"maps jvm failed"`; `…:"maps messages failed"` | `gherkin-results.test.ts:"status matrix › failed" :L42` | RETIRE×2 → table row | – | yes / no |

Columns:
- **Verdict**: `KEEP`, `RETIRE` (the test is removed; its survivor is the *After* cell, which must assert this row's behaviour) or `SPLIT` (the test guarded several rows and is now split into more than one assertion).
- **Security**: `path-confinement`, `size-cap` or `privacy` when the row is one of the C-006 guards. Such a row must never end with zero tests in *After*.
- **Break-checked**: `yes` when the reviewer broke the behaviour and the *After* test went red (FR-004: at least 20% of RETIRE rows; NFR-004: at least one KEEP per family). If a RETIRE row's survivor stays green when the behaviour is broken, the work package is blocked.

One line per removed test, in this format. Reviewers sample from this list.

```
RETIRE <file>:"<test name>" → <file>:"<survivor>" :L<line>  (row <ID>)
```
