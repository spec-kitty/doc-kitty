## Root cause of the black print

- **V** Starlight already prints light: its `dist/style/print.css` sets every
  `--sl-color-*` to light values under `@media print { :root { … } }`.
- **V** doc-kitty overrides that: `src/styles/theme.css:206` (`:root:root`, 0,2,0,
  loaded last) bridges `--sl-color-*` to `var(--dk-*)`, and the `--dk-*` colour
  tokens take their dark values under `:root[data-theme='dark']`
  (`theme.css:149`). The generated sheet does the same
  (`emitTokenSheet`, `theme.ts:480-528`).
- **V** A brand's own `:root[data-theme='dark']` block also wins over a plain
  print sheet: `src/themes/spec-kitty/tokens.css:107`, layered after the
  generated sheet through `customCss` (`config.ts:713-715`).
- **N** The emitter knows only the *resolved object* tokens. A brand that ships
  per-mode colour in a CSS file (spec-kitty's `tokens.css`) has light values the
  emitter cannot see. A generated fallback therefore restates the resolved light
  value for each mode-varying token, scoped to `[data-theme='dark']` under
  `@media print` at (0,3,0); light-theme prints keep the brand's own values. The
  JS hook (which flips `data-theme`) is the primary fix and gives brand-exact
  colours; the CSS fallback gives a clean light print with the Default palette
  for brand CSS tokens. `MODE_VARYING` is `theme.ts:303`.

## Diagrams

- **V** Chromium's `page.pdf()` does not fire `beforeprint`, so the PDF lane must
  set `data-theme="light"` itself.
- **V** Client-mode Mermaid re-renders through a `[data-theme]`
  `MutationObserver`: `src/lib/diagram/diagram-render.client.ts:303-306`. The
  re-render resets each node's text and calls `mermaid.run` asynchronously
  (lines 168-186), so "an `<svg>` exists" can be observed on the stale dark SVG
  or mid-reset. **Consequence:** the client render publishes a completion signal
  (the theme it last rendered) that the PDF lane waits on.
- **V** Existing `@media print` blocks: four in toolkit CSS:
  `src/styles/disclosure.css:133`, `src/styles/dk-openapi.css:161`,
  `src/styles/dk-reveal-theme.css:344` (deck, untouched), and
  `src/styles/dk-components.css:1008` (lightbox triggers only).
- **V** Clipping in print: `.dk-diagram { overflow-x: auto }`
  (`dk-components.css:304`), the JSON-diagram wrapper `overflow-x: auto`
  (`:317`) and `svg[data-diagram-type='JSON'] { max-width: none }` (`:324`).

## Tabs

- **V** There is no tabs component in the repository and no MDX in the example
  (`find example/docs -name '*.mdx'` is empty; no MDX integration in
  `example/astro.config.mjs`). Starlight's `<Tabs>` needs MDX, so a tabs fixture
  would mean adding MDX. **Consequence:** the print rule for `starlight-tabs`
  ships (inert unless a consumer uses MDX tabs) and the tabs assertion of #389/#390
  is descoped with a note.

## `sections.yaml`

- **V\*** `src/lib/vocabulary-loader.mjs:123-151` keeps only
  `id/label/order/type/icon/subtypes` and drops every other key. The Astro side
  re-reads the legacy file with the full-fidelity parser
  (`src/lib/sections.ts:259-268`), whose `normalizeSectionEntries`
  (`sections.ts:139-210`) is where `feeds?: string[]` is carried (line 61 type,
  lines 177-179 parse). A `pdf:` key is dropped by BOTH normalizers today, so a
  gate reading the registry would see no PDF sections and pass vacuously.
  **Consequence:** extend the type, `normalizeSectionEntries`, and the bare-Node
  normalizer (the gate and the PDF CLI read the registry outside Astro).

## Route model

- **V** Injected-route precedent: `src/lib/integrations/page-atom.ts:15-41`
  (`injectRoute` with a package-export entrypoint, options through a virtual
  module) and `src/lib/routes/page-atom-injected.ts` (getStaticPaths + GET).
  Exports in `src/package.json:34-37`.
- **V\*** Route collision checks are the OpenAPI ones,
  `config.ts:644-646` (`openApiCollisionMessage`); a `/print/` reservation needs
  its own check.
- **V** The one-`<h1>` gate: `src/scripts/assert-build-artifacts.mjs:2658-2688`
  walks every built HTML page. A print document holding several pages must keep
  one `<h1>` and demote each page title.
- **V** Sitemap count pins: `EXPECTED_SITEMAP_URL_COUNT = 78`
  (`assert-build-artifacts.mjs:192`) and the index pin (`:157`). The sitemap
  filter composes registered predicates (`config.ts:980`,
  `src/lib/openapi/materialise.mjs:236` `registerSitemapPredicate`); a print
  predicate keeps the pins unchanged.
- **V** Pagefind: Starlight marks the page body `data-pagefind-body` unless the
  route sets `pagefind: false` (`src/lib/schema.ts:772-788` uses the same switch
  for drafts). The print route must set it.
- **V** `noindex` precedent: `src/components/Head.astro:64`.
- **N** llms.txt, the agent API, RSS and the OKF bundle enumerate the docs
  collection, not built routes, so an injected print route never reaches them.
- **V** Anchors: every printed page renders headings with slug ids; two pages
  with an "Overview" heading collide in one document, so ids are prefixed per
  page and in-section links are rewritten to those anchors.

## Build-time vs post-build

- **V** `src/lib/served-surfaces.ts` derives surfaces from injected route
  patterns and config at `astro:config:done`; `assert-build-artifacts` runs on a
  dist before any PDF exists. PDFs are written after the build, so the download
  link, `served-surfaces` and the expected-artifact list are driven from config
  (the resolved `pdf` settings), never from `dist/pdf/` on disk.

## CI

- **V** `.github/actions/build-example/action.yml:76-104` caches and installs the
  Playwright Chromium matching `@playwright/test@1.62.1`.
- **V** The a11y lane (`.github/workflows/ci.yml:442-490`) runs in
  `mcr.microsoft.com/playwright:v1.62.1-noble` on the `example-dist` artifact
  (drafts ON), plus `example-dist-nodrafts` (drafts OFF, uploaded at
  `ci.yml:347-353`). The deploy builds drafts OFF (`deploy.yml`, `DK_PUBLISH_DRAFTS:
  'off'`), so PDF determinism and the gate run on `example-dist-nodrafts`.
- **V** `REQUIRED_LANES` (`.github/scripts/ci-ok-decision.mjs:25-31`) fails closed
  on a missing input, and there is no advisory-lane precedent. A new lane that is
  not in `REQUIRED_LANES` is advisory by construction; joining `ci-ok` is an
  operator decision (escalation).
- **V** `diffDist` (`tests/consumption/openapi-optin.test.ts:131-149`) normalises
  through utf8 strings; unsound for binary PDF. The determinism test compares
  raw `Buffer`s and reports the first differing offset and its object.
- **V** No PDF parser on runners and no `pdffonts`. **N** `playwright@1.62.1` is
  already an *optional peer dependency* of `@spec-kitty/doc-toolkit`
  (`src/package.json:86,95-97`), so a `dockitty-pdf` CLI reusing it adds no
  dependency. Chromium's Skia writer emits classic xref tables, so date pinning
  and the `Producer` stamp can be a fixed-width patch plus a standard PDF
  incremental update, with Node built-ins only (no `pdf-lib`).
