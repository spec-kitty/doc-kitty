# Research: Sidebar, TOC rail and page-frame remediation with Header carrier

Evidence comes from the 2026-10-13 review of the published site (live measurements at six widths, a 68-page crawl) and from reading the current source. No dependency is added, so there is no supply-chain decision to challenge.

## R1 — Frame width token

- **Decision**: add `--dk-width-frame`, default `100%`, declared in `theme.css` and `DEFAULT_BASE`, and registered with `@property` (`<length-percentage>`, inherits, initial `100%`) in `dk-components.css`. The frame rule becomes `width: 100%; max-width: var(--dk-width-frame); margin-inline: auto` at the desktop breakpoint, replacing the `min-width: 100rem` block.
- **Rationale**: the current cap fails because auto margins on a child of a column flex container suppress stretch, so the frame shrink-wraps (measured 1056px against an intended 1440px). `width: 100%` fixes that. Registration makes an invalid value fall back to the initial value instead of invalidating the declaration.
- **Alternatives considered**: keep a fixed 90rem cap (rejected by owner decision 1); a JS-measured frame (rejected: no measurement in the layout path, and it would shift after paint).

## R2 — Sidebar and header follow the frame

- **Decision**: define a gutter custom property, `max(0px, (100vw - var(--dk-width-frame)) / 2)`, on the root. Offset the fixed left sidebar by it on the inline-start side. Keep the header bar full-bleed and inset its content by the same gutter, using a selector that includes the `data-has-sidebar` attribute so it out-specifies Starlight 0.32's own header rule.
- **Rationale**: both elements are `position: fixed` and so ignore the frame's centring; the earlier fix documented this as a deliberate non-fix. With the default 100% the gutter is 0 and nothing moves.
- **Alternatives considered**: capping the header element itself (measured worse earlier: it detaches from the sidebar); making the sidebar non-fixed (changes scroll behaviour).
- **Open point for implementation**: a percentage frame value inside a `100vw` subtraction resolves against the viewport only if the token is a length; the registered property computes percentages, so the gutter must be verified for `%`, `rem` and `px` caps in the geometry guard.

## R3 — Rail column width

- **Decision**: at the desktop breakpoint give the rail container and the fixed rail a definite width equal to the sidebar width token, and size the main pane as the remainder, with selectors prefixed so they beat Starlight's (0,3,0) rule.
- **Rationale**: Starlight 0.32 sizes the rail as `sidebar + (100% - content - sidebar) / 2`, which equals the sidebar width only at one viewport. That is the root of the toggle drift (8px at 1280, 280px at 1920).
- **Alternatives considered**: reproducing Starlight's formula in the toggle offset (fragile across Starlight versions and still leaves a growing rail).

## R4 — Toggle placement

- **Decision**: mount the button as the first child of the rail container (before the panel), keep `position: fixed`, and anchor it with `inset-inline-end: calc(gutter + rail width)` when expanded and `inset-inline-end: gutter` when collapsed. Add `aria-controls` pointing at the rail panel, which gets a stable id. Keep `aria-expanded`, the storage key and the root attribute unchanged.
- **Rationale**: DOM position fixes focus order; fixed positioning avoids the rail's overflow clipping; logical properties give right-to-left parity. The container is an ancestor of neither the `pointer-events: none` rail nor the `display: none` panel, so the button stays operable when collapsed.
- **Alternatives considered**: absolute positioning inside the rail (clipped by the rail's scroll overflow; an earlier review hit exactly this with a pseudo-element caret); leaving it on `<body>` with `tabindex` (positive tabindex is an anti-pattern).

## R5 — Sidebar shaping

- **Decision**: register a toolkit route-data middleware that post-processes the resolved sidebar: for each group that corresponds to a directory, take the label from that directory's index page title, order siblings by the index page's declared sidebar order then by label with the project's code-unit comparator, and move the index entry to the front. The shaping is a pure function over the sidebar tree plus a directory-metadata map built once from the docs index. A group with no index title gets a humanised directory name and a build warning.
- **Rationale**: Starlight 0.32 autogeneration labels subgroups with the directory name and offers no per-directory label; route-data middleware (available from 0.32) is the supported place to rewrite it, and it leaves a consumer's own `sidebar` config authoritative when the middleware only touches autogenerated groups.
- **Alternatives considered**: generating an explicit nested sidebar config from the tree (duplicates Starlight's treeify, loses per-page `sidebar` front matter handling); a new `_meta` file per directory (new authoring surface the spec's assumptions rule out).
- **Spike first**: confirm the middleware can replace `sidebar` and `toc` on Starlight 0.32.6 and that the result is identical on every page. **Fallback** if it cannot: build the nested sidebar config at config time from the docs index.

## R6 — Revealing the current entry

- **Decision**: a small inline script, placed with the sidebar, scrolls the `aria-current="page"` entry into view with `block: 'nearest'` only when Starlight's persisted sidebar scroll state is absent or leaves the entry out of view.
- **Rationale**: measured: on a deep page the active entry sat at y=1621 with the sidebar at scroll position 0. Running before first paint avoids visible movement.
- **Alternatives considered**: collapsing non-ancestor groups by default (changes a behaviour readers may rely on; left as a possible follow-up).

## R7 — Near-empty table of contents

- **Decision**: in the same route middleware, drop the table of contents when it has no entry besides the page-title "Overview" entry, so Starlight renders the page without a rail.
- **Rationale**: 360px of rail is reserved for a single link on hub and persona pages.
- **Alternatives considered**: CSS-hiding the rail (leaves `data-has-toc` and the reserved column in place).
- **Related**: raise TOC link target size to the 24px minimum in `toc-rail.css` and remove the front-matter TOC suppression on the diagram demonstrator page that existed to dodge it.

## R8 — Draft publication setting

- **Decision**: `DK_PUBLISH_DRAFTS` with accepted values `on` and `off`, default `off`, resolved by a pure module shared between the integration and the `.mjs` gates. The integration reads it from the process environment first and otherwise from the site's env files, so `example/.env.development` (value `on`) applies to the dev server and not to production builds. *Corrected 2026-10-13:* the toolkit reads the env files with a small built-in reader, not through the build tool's env loader, because that loader is not resolvable from the installed package. The reader has these limits: mode is `development` for `astro dev` and `production` for everything else, so `astro build --mode staging` does not read `.env.staging`; Vite's `envDir` is ignored; only `DK_*` keys are read; variables are not expanded and Vite's quoting rules are not followed exactly. Redirect withholding works on static output only: under an adapter that emits host-level redirects, or under SSR, a redirect to a draft is not withheld. The gates call the same resolver as the integration (`--site-root`, `--mode`). Any other value fails the build with the accepted values named.
  - **Off**: draft entries are filtered out where the docs collection is loaded, so no page, sidebar entry or search record exists.
  - **On**: drafts are built and listed, and the Head carrier adds a `noindex` robots meta to them.
  - Machine surfaces exclude drafts in both cases, as today.
- **Rationale**: filtering at the loader gives one cut that every HTML surface inherits. Mode-specific env files give "on locally, off live" without anyone remembering a flag; the live workflow also sets `off` explicitly so the intent is visible there.
- **Alternatives considered**: Starlight's native `draft` front matter (a second, parallel draft notion next to `doc_status`); hiding drafts from the sidebar only (pages stay reachable); default on (fail-open: a deployment that forgets the flag leaks drafts).
- **Consequences to plan for**: route lists, the URL baseline and the hub draft-exclusion guard currently run against a build that contains drafts. CI's main example build runs with the setting on so those keep their coverage, and a second assertion builds with it off and checks that zero draft routes exist and the link gate is clean. The deploy workflow's "same build as the PR gate" note is updated to state the one intended difference.

## R9 — Header carrier

- **Decision**: `src/components/Header.astro` renders the theme's `dk:site-header` slot component when the manifest has one, otherwise Starlight's default header, with no wrapping element. It joins the carriers map; the manifest gains the slot; the package exports the component. ADR-0044 supersedes the four-carrier clause of ADR-0013 and ADR-0015 and states the replacement contract: search, theme switch, mobile menu control and skip link become the theme's responsibility.
- **Rationale**: owner decision 3. A carrier that only forwards to the default is byte-neutral, which a before/after build diff proves.
- **Alternatives considered**: sub-slots inside the stock header (Starlight renders the header itself; there is nothing to slot into without overriding it).

## R10 — Guards

- **Decision**: a new Playwright spec measures bounding boxes at 1152, 1280, 1600, 1920 and 2560 in expanded and collapsed states, in left-to-right and right-to-left, with a capped-frame variant and an invalid-token variant injected through a style override. A Vitest CSS-contract test checks that the rules live in the brand-surviving sheet, are desktop-gated, and that `theme.css` and `DEFAULT_BASE` agree on the token. The spec is committed first in a state that fails on the current layout.
- **Rationale**: the existing guard runs only at 1280, where the error is 8px.
- **Alternatives considered**: visual baselines alone (they pass whenever someone regenerates them).

## R11 — Second decision record

- **Decision**: ADR-0045 records the frame-width token, the full-width default and the withdrawal of the "layout unchanged below 100rem" constraint from the wide-frame work.
- **Rationale**: FR-030; the geometry change would otherwise read as a regression against an accepted constraint.
